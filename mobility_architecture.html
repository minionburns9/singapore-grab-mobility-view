Singapore Taxi & Mobility Decision View

Simple system architecture for the live taxi mobility app built on LTA DataMall, Render/FastAPI, and Mapbox. The diagram shows the main systems and data flow. Detailed inputs, outputs, assumptions, and system considerations are listed below the diagram.

Security / Data Handling Legend

[E-T]
Encryption in Transit HTTPS / TLS protects Browser ↔ Render, Browser ↔ Mapbox, and Render ↔ LTA DataMall traffic.
[E-R]
Secrets at Rest LTA AccountKey and Mapbox token are stored as server-side environment variables in Render, not in GitHub source code.
[A]
Access Control LTA AccountKey is used only on the backend. The browser never calls LTA directly.
[P]
Privacy / Data Minimization User location is used only after browser permission. It is sent to the backend only to calculate local readiness and 1km mobility choices.
[D]
Derived Analytics Fare Pressure Proxy is derived from public signals such as taxi availability, traffic incidents, slow segments, and nearby alternatives. It is not actual Grab pricing.

Inputs

  • User interaction: view selection, “My Location” tap, map interaction, and refreshes.
  • User location (optional): browser geolocation coordinates, only after permission is granted.
  • LTA live datasets: Taxi Availability, Bus Stops, Taxi Stands, Traffic Incidents, Traffic Speed Bands, and Train Service Alerts.
  • Mapbox assets: basemap styles and tiles for rendering the interactive map.
  • Server-side configuration: MAPBOX_TOKEN and LTA_ACCOUNT_KEY stored in Render environment variables.

Outputs

  • Live Taxi Supply Hexmap: citywide view of available-for-hire taxis grouped into translucent hex cells.
  • Pickup Readiness: local taxi-only decision support within 300m / 600m / 1km, including nearby supply and pickup context.
  • 1km Mobility Choices: top 3 recommended local options such as taxi / taxi stand / bus stop / MRT, with approximate walking time.
  • Fare Pressure Proxy: derived indicator of pickup difficulty based on public signals only.
  • Disruption overlays: traffic incidents, slow road segments, bus stops, taxi stands, and train alerts.
  • Operational / debug endpoints: health checks, config, and API responses for validation.

System Considerations

  • No direct LTA calls from browser: the client always calls the FastAPI backend; LTA credentials remain server-side.
  • Encryption: all external traffic should use HTTPS/TLS. This protects user-to-app, app-to-LTA, and app-to-Mapbox communication.
  • Secrets handling: LTA AccountKey must never be committed to GitHub or exposed in browser JavaScript.
  • Token exposure model: Mapbox uses a public browser token; this is acceptable, but it should ideally be URL-restricted.
  • No durable application database: the current app is designed as a live, read-mostly view with on-the-fly calculations.
  • Rate / reliability: LTA and Mapbox external dependencies may affect app responsiveness. Simple caching and retry handling would be a good future improvement.
  • Privacy: the app should avoid storing precise user location persistently unless a later product requirement explicitly needs it.

Assumptions

  • LTA Taxi Availability scope: the feed is treated as live available-for-hire taxis in Singapore. It does not include hired/busy taxis.
  • No private-hire / platform detail: the app does not know whether a taxi is on Grab, Zig, Gojek, TADA, or street-hail only.
  • No actual Grab pricing: the app does not receive real Grab fare or surge APIs, so “Fare Pressure Proxy” is only a public-data estimate.
  • Mobility choices are local, not full routing: the current app does not use destination input, so recommendations are based on local proximity and system conditions, not full trip optimisation.
  • Walking time is approximate: calculated from simple distance assumptions rather than full pedestrian network routing.
  • MRT station layer: MRT station points are reference locations; live disruption status comes from LTA Train Service Alerts.
Recommended label for the product:
Singapore Taxi & Mobility Decision View

This naming is more accurate than “Grab Mobility View” because the app is built from public LTA DataMall transport signals rather than operator-specific Grab APIs.
